# Palm Engine

브라우저에서 JPEG/PNG/WebP(최대 10MB)를 decode → 600px 너비 canvas → 자동 선 제안 → 사용자 확정 → 정규화 좌표 폴리라인 → 길이·곡률 feature. 원본 파일이나 canvas 이미지는 서버로 전송하지 않습니다.

## 자동 인식 파이프라인

`src/domain/palm-vision.ts`는 DOM에 의존하지 않는 순수 함수입니다. 입력은 RGBA 픽셀 버퍼, 출력은 수동 표시와 동일한 정규화 좌표 폴리라인이므로 이후 단계는 입력 방식을 구분하지 않습니다.

| 단계 | 방법 | 이유 |
| --- | --- | --- |
| 1. 피부 분할 | YCbCr 색차 임계 | 색차는 휘도보다 피부톤 차이에 덜 민감합니다 |
| 2. 손 분리 | 최대 연결 성분 | 배경이나 다른 피부 영역이 선택되지 않게 합니다 |
| 3. 손바닥 위치 | 거리 변환의 최대 내접원 | 손가락이 아닌 손바닥 중심을 잡습니다 |
| 4. 방향 정규화 | 마스크 2차 모멘트 주축, 먼 쪽을 손가락으로 판정 | 촬영 각도에 무관한 ROI를 만듭니다 |
| 5. ROI 추출 | 내접원 반지름 2.1배 정사각형을 160×160으로 bilinear 리샘플 | 손 크기와 무관한 고정 좌표계 |
| 6. 선 응답 | box blur 후 (주변 평균 − 픽셀), 최대값 정규화 | 손금은 주변보다 어두운 골입니다 |
| 7. 선 추적 | 감정선·두뇌선은 열 방향 argmax, 생명선은 행 방향 argmax | 감정선/두뇌선은 가로로, 생명선은 엄지 쪽을 세로로 지납니다 |
| 8. 신뢰도 | 평균 응답 × 연속성 | 진행 방향이 아닌 이탈 축의 흔들림만 감점합니다 |

학습 모델을 쓰지 않으므로 같은 사진이면 항상 같은 결과가 나옵니다. 신뢰도가 0.18 미만인 선은 버리고 해당 선을 "찾지 못함"으로 표시합니다.

엄지 위치는 선택한 손(`left`/`right`)으로 결정합니다. 카메라를 향한 손바닥에서 왼손은 엄지가 이미지 오른쪽에 옵니다.

## 사용자 확정

자동 결과는 제안입니다. 선별 신뢰도를 뚜렷함/보통/흐림으로 표시하고, 기존 수동 표시 UI가 그대로 편집기가 됩니다. 점을 다시 찍거나 `지우고 직접 표시`로 전체를 비울 수 있습니다. 손을 찾지 못하면 이유를 밝히고 수동 입력으로 진행할 수 있게 합니다.

양손 사진을 별도로 선택할 수 있으며 같은 선을 양손에서 측정하면 평균을 사용합니다. 길이는 이미지 좌표 공간 기준이라 손 크기와 촬영 구성에 영향을 받습니다.

## Feature

`measureLines`가 폴리라인에서 두 값을 만듭니다.

- `*_line_length` — 정규화 폴리라인 길이
- `*_line_curve` — 폴리라인 길이 ÷ 직선 현. 0이면 직선, 커질수록 휩니다

`head_line_curve`는 Trait 매핑(적응력)이 소비하는데 이전에는 어디서도 생성되지 않는 죽은 값이었습니다. 이제 자동·수동 양쪽에서 생성됩니다.

source는 demo/manual/none입니다. source=none은 특징을 제외하고, 측정하지 못한 값은 만들어내지 않습니다.

## 하지 않는 것

깊이, 분기 개수, 지문, 손금의 전통적 의미 판독, 장수·건강·질병 추론은 구현하지 않습니다. 확장 schema에 자리는 있으나 생성하지 않는 값은 비워 둡니다.

정확도는 조명, 배경 대비, 손 각도, 카메라 품질에 따라 크게 달라집니다. 실제 사람 손 데이터셋에 대한 정확도 측정은 수행하지 않았고, 합성 손바닥 이미지로 파이프라인 동작만 검증합니다. 그래서 결과를 확정이 아닌 제안으로 제시합니다.

## 확장

`PalmFeatureExtractor` 인터페이스는 `source: "manual" | "automatic"`과 `limitations`를 반환하도록 정의돼 있습니다. MediaPipe hand landmark로 4단계 방향 정규화를 대체하면 기울어진 손과 부분 가림에 강해집니다. 교체 시 결정성과 오프라인 동작이 사라지므로, 실제 검출 품질 데이터를 확보한 뒤 판단해야 합니다.

손금이 전체 Trait 가중치에서 차지하는 비중은 약 1.4%(1,438 중 20)입니다. 인식 정확도를 올려도 판정 결과는 거의 바뀌지 않습니다. 이 기능의 목적은 점수 정확도가 아니라 기록을 직접 읽어 준다는 경험입니다.
